# Getting Started

Last updated: 2026-10-11

BrewPage is a free hosting platform for HTML pages, key-value data, JSON documents, files, and multi-file sites. No signup required — publish content instantly.

## What You Can Publish

- **HTML / Markdown** — Single-page hosting, auto-rendered Markdown, optional password protection
- **KV** — Key-value store, up to 1,000 keys per store, 1 MB per value
- **JSON** — JSON document store, up to 10,000 docs per namespace, 1 MiB per doc
- **Files** — File hosting, up to 5 MB per file, 1,000 files per namespace
- **Sites** — Multi-file HTML site hosting via ZIP or individual files, up to 200 files, 5 MB per file, 20 MB total, TTL 1–30 days

Current upload limits are published as JSON at [`GET /api/limits`](https://brewpage.app/api/limits); read them before uploading a large or multi-file site.

**Base URL:** `https://brewpage.app` (`https://brewdata.app` redirects to it with 301)

### 4. REST API

  { title: "POST your content", description: "Send content in the JSON body; select namespace, format, and TTL through query parameters" },

REST and MCP both default to private: unlisted and not indexed; anyone with the link can still open it. These examples explicitly select `public`, which lists HTML, sites and files in the gallery and sitemap for Google, Bing and AI search. Password-protected publications are never listed. Ordinary TTL is 1–30 days, default 15; owner-specific caps and eligible automatic extensions can affect expiry. Use returned `expiresAt`.

**Publish HTML:**

```bash
curl -X POST 'https://brewpage.app/api/html?ns=public&format=html' \
  -H "Content-Type: application/json" \
  -d '{"content":"<h1>Hello World</h1>"}'
```

**Publish Markdown:**

```bash
curl -X POST 'https://brewpage.app/api/html?ns=public&format=markdown' \
  -H "Content-Type: application/json" \
  -d '{"content":"# My Notes\n\nMarkdown is **auto-rendered**."}'
```

**Upload a file:**

```bash
curl -X POST 'https://brewpage.app/api/files?ns=public' \
  -F "file=@image.png"
```

**Illustrative NEW public Promotion response (additional fields omitted):**

```json
{
  "namespace": "public",
  "id": "aBcDeFgHiJ",
  "link": "https://brewpage.app/public/aBcDeFgHiJ",
  "ownerLink": "https://brewpage.app/api/html/public/aBcDeFgHiJ",
  "ownerToken": "tok_abc123...",
  "routingCohort": "new-v1",
  "deliveryMode": "path",
  "hostingVersion": 1
}
```

> **Save your `ownerToken`!** You need it to update or delete content later. It cannot be recovered.

NEW publications default to Promotion (`path`) in any namespace and may choose Dedicated subdomain with `X-Delivery-Mode: subdomain`, except NEW sites and non-public HTML pages of format `html`, which always use Dedicated subdomain (an explicit `path` is reported, not rejected); each site bundle has one publication-specific host with native paths and 404 responses for missing files. Use returned links including root slashes. NEW protected links stay clean: browser readers unlock through the trusted gateway; API reads use `X-Password`. OLD publications retain their existing links and behavior, including when creation reuses an existing winner. See the [MCP hosting guide](/brewpage-openapi/mcp-server/#visibility-and-delivery) for owner hosting changes.

## More API Examples

**Store key-value data:**

```bash
curl -X POST 'https://brewpage.app/api/kv?ns=public' \
  -H "Content-Type: application/json" \
  -d '{"key":"theme","value":"dark"}'
```

Read with `GET /api/kv/{namespace}/{id}/theme` using the returned identity. Updates use `PUT` on that route with `X-Owner-Token` and `{"value":"light"}`.

**Store JSON document:**

```bash
curl -X POST 'https://brewpage.app/api/json?ns=public' \
  -H "Content-Type: application/json" \
  -d '{"name":"Alice","role":"admin"}'
```

**Platform stats:**

```bash
curl https://brewpage.app/api/stats
```
