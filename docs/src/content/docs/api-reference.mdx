Hosting GET supports `html`, `files`, `json`, `kv`, and `sites`; hosting PATCH supports only `html`, `files`, `json`, and `kv`. Reader-access revocation supports all five types.

## Authentication

Unprotected publication reads need no credential, including unlisted content whose link is known. Password-protected reads require access; owner listing and mutations require owner authority. Admin endpoints require separate administrative authentication.

Owner mutations use the original token returned at creation:

| Method | Example |
|--------|---------|
| Header | `X-Owner-Token: tok_xxx` |

Programmatic protected reads:

| Method | Example |
|--------|---------|
| Header | `X-Password: secret` |

NEW protected browser links use the clean returned `link` and a trusted top-level unlock gateway. Never append passwords or owner tokens to NEW share URLs. OLD publications retain historical access behavior, including legacy query-password parsing where supported; this is not the NEW browser unlock mechanism. API and owner operations remain on the apex, not content hosts.

## Publication Delivery

REST creation defaults to `ns=public`; the MCP wrapper defaults to an unlisted generated namespace. Only unpassworded `public` content is eligible for gallery/search discovery. Dedicated content hosts carry `noindex`.

For fresh NEW publications, public non-sites default to **Promotion** (`path`) and may select **Dedicated subdomain** with `X-Delivery-Mode: subdomain`. Sites and non-public publications require Dedicated subdomain; explicit `path` is rejected. Every NEW site bundle has a publication-specific host with relative/root-relative paths and native missing-file 404 responses, without an SPA fallback. Promotion has stricter active-document restrictions.

Keep the returned primary `link` exactly, including root slashes; do not reconstruct a host from namespace or ID. Responses expose cohort, actual/requested/effective modes, `deliveryModeMatched`, `modeLocked`, `hostingVersion`, `access`, and an apex `managementLink`. An existing deduplication winner retains its own cohort, link, and mode. OLD links remain compatible and show **Existing link**, with missing or null effective-mode metadata.

An eligible NEW public non-site can change hosting through owner-only `PATCH .../hosting` with `{"deliveryMode":"subdomain","expectedVersion":1}` using its current `hostingVersion`. Sites, non-public publications, and OLD links are locked. Wrong owner returns 403, locked mode 400, stale version 409, and a paused real change 503. Current-mode no-op preserves the version; ordinary content updates and site republishing preserve hosting. The reserved publication host survives both switch directions.

Owners can revoke reader access for a NEW protected publication through `POST .../access/revoke` with `X-Owner-Token` and no body. Readers must unlock again; other publications and offline copies are unaffected.

## Rate Limits

Limits depend on operation and visibility. Handle the running API's 429 responses and any `Retry-After` header rather than assuming a single upload quota.

## Size Limits

| Resource | Max Size | Max Count |
|----------|----------|-----------|
| HTML page | 5 MB | — |
| KV value | 1 MB | 1,000 keys/store |
| JSON doc | 1 MB | 10,000 docs/namespace |
| File | 5 MB | 1,000 files/ns |
| Site | 20 MB total, 5 MB/file | 100 files/site |
| TTL | 1–30 days (default 15) | — |

These are repository defaults; video uploads allow up to 20 MB. The running deployment may apply stricter limits.

## Try It Now

```bash
curl https://brewpage.app/api/stats
```

```bash
curl -X POST 'https://brewpage.app/api/html?ns=public&format=html' \
  -H "Content-Type: application/json" \
  -d '{"content":"<h1>Hello!</h1>"}'
```
