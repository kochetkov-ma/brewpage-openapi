# Changelog

## Spec 1.104.0 / MCP 1.9.0 — Delivery reason on HTML responses

`POST /api/html` and `PUT /api/html/{ns}/{id}` responses may now carry two optional strings, `deliveryModeReason` and `deliveryNotice`. A public HTML or Markdown page created without `X-Delivery-Mode` may be published on its own subdomain when it needs browser features a BrewPage link does not provide; the response then says `auto:<codes>`. `advisory:<codes>` means the address was not changed. Send `X-Delivery-Mode: path` to keep a BrewPage link, and always use the returned `link`. Existing clients see no difference when the fields are absent.

The spec also documents `visibilityNotice` on HTML responses, `result` on the update response, the optional `format` on `PUT /api/html/{ns}/{id}`, and the `200` response with `X-Existing-Resource: 1` returned when a repost matches a page that is already published.

MCP 1.9.0: `publish_html` and `update_html` print `deliveryModeReason` and a `Delivery notice:` line when the server returns them. Same sixteen tools, no input changes.

## Spec 1.31.0 / MCP 1.4.0 — Content-Type fallback on `POST /api/html`

`POST /api/html` and `PUT /api/html/{ns}/{id}` now accept raw `text/*` bodies and (POST only) `application/octet-stream`. Binary payloads sniffed as PNG, JPEG, GIF, WEBP, MP4, PDF or ZIP auto-route to `/api/files` and return a 201 with the file resource location. The existing `application/json` contract is unchanged — JSON clients see no difference.

`UnsupportedFileTypeException` now responds with **422 Unprocessable Entity** (was 415). Both 415 and 422 error bodies expose a `supportedTypes` array on `ErrorResponse` listing the MIME types the endpoint accepts, so clients can surface actionable guidance.

For the full MIME → format dispatch table and ready-to-paste `curl` examples, see the live BrewPage [`/llms-full.txt`](https://brewpage.app/llms-full.txt). The interactive OpenAPI explorer is published at [kochetkov-ma.github.io/brewpage-openapi](https://kochetkov-ma.github.io/brewpage-openapi/).
