# Changelog

## MCP 1.22.0 — custom domains that get finished

The assistant now leads you through your own domain step by step. If your owner token is not in a profile yet, it gives you the token and the one thing only you can do: sign in at https://account.brewpage.app/tokens, press Add existing token and paste it. It hands you the exact DNS records to create (keep your mail records; at Cloudflare set Proxy status to DNS only), checks once after you created them and then reads the status until the domain is live, usually within 30 minutes; if something blocks it, the result names the fix. `list_domains` can read one custom domain by page or hostname without a new DNS check, and `get_guide` has a second topic, `custom-domain`. Thirty-two tools, contract 2.28.0.

## MCP 1.21.0 — usage counts on the hosted server

The hosted server at `https://brewpage.app/mcp` counts calls per tool, Claude, ChatGPT and other clients, and distinct clients per day, for our own monitoring only; no addresses, content or tool inputs are kept. Tools and inputs are unchanged: thirty-two tools, contract 2.27.0.

## MCP 1.20.0 — make private, hide the badge

Two new tools. `make_private` turns a public page into a private one: it gets a new private link and the public link stops working; views and stats stay. It is one-way, and the assistant gives you the new link and the management link. `set_badge` hides or shows the BrewPage badge on a page of your profile, up to 5 hidden. `set_visibility` now reads as list or unlist; inputs unchanged. The assistant is told not to hide the badge in page code and to use `set_badge` instead. Thirty-two tools. Contract 2.27.0.

## API contract 2.27.0 — hide the badge, make private

Two new owner operations. `POST /api/{type}/{ns}/{id}/badge` (`setBadge`, body `{hidden}`) hides or shows the BrewPage badge on a publication of a profile, up to 5 hidden per profile; a sixth hide answers 409 `BADGE_HIDDEN_LIMIT`. `POST /api/{type}/{ns}/{id}/private` (`makePrivate`) gives a public publication a new private link; the public link answers 410, and it is one-way. Items of `GET /api/publications` add `badgeHidden`. Listing texts say list or unlist instead of hide or show; no path, field or code renamed. 61 paths and 83 operations (were 59 and 81).

## API contract 2.26.0 — feature chips on gallery items

Items of `GET /api/gallery` add `chips`: `page-data` when the page saves what visitors enter, `custom-domain` when it has its own domain, in that order, empty when none. The default answer and `mine=true` both carry it. Still 59 paths and 81 operations. The MCP server is unchanged.

## API contract 2.25.0 — file upload answers always include listed and listable

The `POST /api/files` answer now declares `listed` and `listable` as always present, like the HTML create and update answers and the file update answer. The server already sent both on every upload, so nothing changes on the wire; clients and code generators can read them without a presence check. Still 59 paths and 81 operations. The MCP server is unchanged.

## API contract 2.24.0 — what the gallery can list

Answers now say whether a publication can appear in the gallery at all: the new boolean `listable` is `false` for the types that are never listed whatever the namespace (JSON and KV, JSON pages, HTML and JSON files), where Hide and Show do not apply. It comes on HTML create and update answers, file answers, the hosting read, the items of `GET /api/publications` and your own items of `GET /api/gallery`. Items of `GET /api/publications` also add an optional `pageData` with the number of stored entries and the share of the quota in use. Additions and wording only: 59 paths and 81 operations. The MCP server is unchanged.

## MCP 1.19.1 — setup guide on npm

The package page on npm shows the current setup guide: the remote server `https://brewpage.app/mcp` first, with steps for Claude and ChatGPT; the local `npx -y brewpage-mcp@1.19.1` server as the fallback; no global install. The server is unchanged: thirty tools, contract 2.22.0.

## MCP 1.19.0 — page data

A published page can save what its visitors enter: form answers, a guestbook, votes, scores, game progress. The assistant reads the new `get_guide`, then publishes with `state` on `publish_html` or `publish_site`. Four more tools work with the saved entries: `get_page_data` reads them, `set_page_data` writes author entries, `configure_page_data` changes who can read a list, `delete_page_data` removes entries. They take the owner token, or the page's management link as `manageUrl`. After publishing, the assistant gives you the page link and the management link. Thirty tools. Contract 2.22.0.

## API contract 2.22.0 — page data

New tag `Page data` with 6 operations for what visitors saved on your HTML page or site: read the settings and usage (`GET /api/{ns}/{id}/state`), change the settings (`PATCH`, `{}` turns page data on, `null` turns it off and keeps the entries), list one list's entries (`GET …/state/{col}`, also as CSV), write an author entry (`PUT …/state/{col}/{key}`), delete one entry or a time range. Auth: `X-Owner-Token`, or `X-Manage-Key` from the management link. `POST /api/html`, `PUT /api/html/{ns}/{id}`, `POST /api/sites` and `PUT /api/sites/{ns}/{id}` take an optional `state`; the page gets its own address `https://<label>.brewpage.app`. New `GET /api/gallery/promo` returns BrewPage's own examples pinned in the public gallery. Additions only: 59 paths and 81 operations.

## API contract 2.21.8 — JSON files on upload

The file upload response tells clients that JSON files are not listed in the gallery and that JSON data belongs in `/api/json`. Description only: 54 paths and 74 operations.

## API contract 2.21.6 — explicit anonymous access

Every operation now states how it is accessed: the 13 that need no credentials (reports, previews, galleries, stats, sitemaps, owner-token minting, random namespace) declare anonymous access, so API catalogs and code generators import the spec cleanly. No path, field or behaviour change: 54 paths and 74 operations.

## MCP 1.18.1 — management link for the user

After publishing, the assistant gives you the management link together with the page link, so you can edit or delete the publication later. The link is private: anyone who has it can edit or delete the publication, so it is never posted publicly. No tool or input change. Contract 2.20.5.

## API contract 2.20.5 — management link wording

`manageUrl` on create answers is described as the management link: give it to the user with the link; private, never post it publicly. `ownerToken`: keep it, send it as `X-Owner-Token` on later publishes and updates, show it to the user on request. Description only: 54 paths and 74 operations.

## MCP 1.18.0 — custom domains

Four new tools put a page or site on a domain you own. `set_domain` connects the domain and returns the DNS records to create at your DNS provider; `check_domain` reports the status until it is `active`; `list_domains` lists the profile's domains; `remove_domain` frees a slot. `publish_html` and `publish_site` take an optional `domain`. Free, 5 per profile, with the owner token in a BrewPage profile. Twenty-five tools. Contract 2.19.0.

## API contract 2.19.0 — custom domains

New tag `Custom Domains`, 11 operations: show one HTML page or one site on a hostname you own, free with a BrewPage profile. `PUT /api/publications/{type}/{ns}/{id}/domain` (`setPublicationDomain`, body `{"hostname"}`) answers a `DomainItem` with the DNS `records[]` to create at your DNS provider; `POST …/domain/check` moves `status` from `pending_dns` to `verifying` to `active`. Also `GET` and `DELETE` on the same path, and the profile routes under `/api/domains` (admin token). `POST /api/html` and `POST /api/sites` take an optional `domain` and answer `customDomain`. Additions only: 54 paths and 74 operations.

## MCP 1.17.0 — rename pages and sites

New tool `set_title`: rename an HTML page or site you own. The title shows in the gallery, your profile, search and link cards, and stays when you republish; an empty title brings back the one from the page. Needs the owner token in a BrewPage profile. Twenty-one tools. Contract 2.16.0.

## API contract 2.16.0 — rename

New `POST /api/{type}/{ns}/{id}/title` (`setTitle`, `html` or `sites`): owners whose token is in a profile set a title of 1-200 characters that survives republish; an empty title restores the one from the content. Answer `{"title","custom"}`; error code `TITLE_INVALID`. 48 paths and 63 operations.

## MCP 1.16.10 — file format order

`publish_html`, `publish_file` and `update_html` state the format order. `publish_file`: HTML and Markdown become pages in any namespace. `update_html`: a whole HTML document makes a Markdown page an HTML page. Contract 2.10.2.

## API contract 2.10.3 — format order in the contract

The generated contract now names the whole file format order, notice `file-format-applied` and `?dl=1` on `GET /api/html/{ns}/{id}`, which were live since 2.10.2. 47 paths and 62 operations.

## API contract 2.10.2 — files and pages

`POST /api/files` publishes HTML and Markdown as pages in any namespace, with or without a password, by one format order: `format`, known extension, specific declared type, content guess, otherwise an inert file. `POST` and `PUT /api/files` take `format`; `PUT` over a file row converts it to a page at the same address. `GET /api/files` does not list such pages; `GET /api/publications` does. `PUT /api/html` with `format` omitted keeps the stored format, except a whole HTML document makes a Markdown page an HTML page. `?dl=1` on `GET /api/html/{ns}/{id}` downloads an HTML or Markdown page's source as an attachment. Notices: `markdown-file-as-page`, `file-format-applied` (published as a code format chosen by `format` or the declared type), `charset-guessed` (no usable charset named, read by guess, saved as UTF-8), `html-file-as-source` (over the page limit or no readable encoding, kept as a file).

## Spec 1.123.0 / MCP 1.12.0 — Upload limits endpoint and clearer site errors

New `GET /api/limits` (`getLimits`, tag `Limits`) returns the user-facing upload limits in bytes: `requestMaxBytes` and `sites` (`maxFiles`, `maxFileBytes`, `maxTotalBytes`, `maxArchiveExpansionBytes`, `maxPathChars`, `maxPathBytes`, `maxNameBytes`, `defaultTtlDays`, `maxTtlDays`, `allowedExtensions`, `skippedFileNames`, `skippedRootFolders`). ## Spec 1.119.0 / MCP 1.11.0 — Fixable inputs accepted with notices

Publish endpoints accept recoverable input mistakes and report each adjustment in an advisory `notices` array of `{code, message}` (`PublishNotice`) on successful create and update responses, omitted when empty. ## Spec 1.118.0 / MCP 1.10.0 — Mismatches reported, not rejected

Publishing and hosting requests no longer fail on delivery-mode or hosting-version bookkeeping. An explicit `path` where Dedicated subdomain is required publishes on the subdomain; a content update that turns a non-public `path` page into format `html` moves it to its subdomain and the old path redirects; `X-Delivery-Mode` on a content update is ignored; the hosting `PATCH` applies a stale `expectedVersion` (now optional) and answers locked modes and OLD links with `200` unchanged. Each such response carries `deliveryModeMatched: false`, `deliveryModeReason` (`policy:<code>`) and a human-readable `deliveryNotice`, now also on the hosting projection. The `PATCH` route also accepts sites and no longer declares `409`. `POST /api/files` no longer requires the multipart part to be named `file`; any single file part is accepted. 32 paths and 46 operations. MCP 1.10.0 `update_hosting` takes an optional `expectedVersion` and prints the notice; same sixteen tools.

## Spec 1.117.0 / MCP 1.9.5 — Delivery rules and safe Markdown

NEW sites and non-public HTML pages of format `html` require Dedicated subdomain; explicit `path` there answers `400 DELIVERY_MODE_REQUIRED`. Everything else in any namespace (Markdown, code/text, files, JSON, KV) now defaults to Promotion (`path`) and may choose `subdomain`; existing publications keep their mode. Markdown raw HTML is rendered through an allowlist: scripts, styles, event handlers, forms, frames/embeds and `meta`/`base`/`link` are removed, while media, `details`/`summary` and links (`http`, `https`, `mailto`, `tel`, relative) stay. Only `X-Delivery-Mode` descriptions and the hosting `PATCH` summary change in the spec: 32 paths and 46 operations. MCP 1.9.5 rewords its tool text accordingly; same sixteen tools and behavior.

## Spec 1.104.0 / MCP 1.9.0 — Delivery reason on HTML responses

`POST /api/html` and `PUT /api/html/{ns}/{id}` responses may now carry two optional strings, `deliveryModeReason` and `deliveryNotice`. A public HTML or Markdown page created without `X-Delivery-Mode` may be published on its own subdomain when it needs browser features a BrewPage link does not provide; the response then says `auto:<codes>`. `advisory:<codes>` means the address was not changed. Send `X-Delivery-Mode: path` to keep a BrewPage link, and always use the returned `link`. Existing clients see no difference when the fields are absent.

The spec also documents `visibilityNotice` on HTML responses, `result` on the update response, the optional `format` on `PUT /api/html/{ns}/{id}`, and the `200` response with `X-Existing-Resource: 1` returned when a repost matches a page that is already published.

MCP 1.9.0: `publish_html` and `update_html` print `deliveryModeReason` and a `Delivery notice:` line when the server returns them. Same sixteen tools, no input changes.

## Spec 1.31.0 / MCP 1.4.0 — Content-Type fallback on `POST /api/html`

`POST /api/html` and `PUT /api/html/{ns}/{id}` now accept raw `text/*` bodies and (POST only) `application/octet-stream`. Binary payloads sniffed as PNG, JPEG, GIF, WEBP, MP4, PDF or ZIP auto-route to `/api/files` and return a 201 with the file resource location. The existing `application/json` contract is unchanged — JSON clients see no difference.

`UnsupportedFileTypeException` now responds with **422 Unprocessable Entity** (was 415). Both 415 and 422 error bodies expose a `supportedTypes` array on `ErrorResponse` listing the MIME types the endpoint accepts, so clients can surface actionable guidance.

For the full MIME → format dispatch table and ready-to-paste `curl` examples, see the live BrewPage [`/llms-full.txt`](https://brewpage.app/llms-full.txt). The interactive OpenAPI explorer is published at [kochetkov-ma.github.io/brewpage-openapi](https://kochetkov-ma.github.io/brewpage-openapi/).
