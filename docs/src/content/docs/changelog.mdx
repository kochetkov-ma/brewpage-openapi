# Changelog

## Spec 1.136.0 / MCP 1.13.0 — Owner features (unreleased)

REST create and list without `ns` publish privately (notice `namespace-defaulted`). Create responses add a private `manageUrl` (give it only to the owner), `listed` and `visibilityUrl`; `access` is an enum. Owner operations accept `X-Owner-Token` or the new `X-Manage-Key` scheme. New operations: `setVisibility`, `setPassword`, `resetManageKey`, `extendPublication`, `rotatePublicationLink`, `replaceFile` (`PUT /api/files/{ns}/{id}`), `hostOwnerCheck`, `bindOwnerToken`, `mintOwnerToken`, `revokeOwnerToken`, `revokeOtherOwnerTokens`, `listPublications`, `getPublicationStats`, `previewWebp` and `ownerPreviewWebp`. Old publications are read-only (`409 OLD_PUBLICATION_READ_ONLY` with `republishUrl`); the KV key `hosting` is reserved; HTML `/settings` adds `readOnly`. The hosting read adds a site's `fileCount` and answers `410` to the owner of a moderated publication. Secrets allowed; likely ones are flagged in notices. For a secret: private namespace + password. 47 paths and 62 operations. MCP 1.13.0 adds `set_visibility`, `bind_token` and `mint_token` (twenty tools), an identifying User-Agent, an optional `BREWPAGE_OWNER_TOKEN` default and site deletion.

## Spec 1.135.0 — Chat-pasted pages repaired, verbatim opt-out

`POST /api/html`, `PUT /api/html/{ns}/{id}` and public `.html` files published as pages via `POST /api/files` repair an HTML page copied from a chat: a wrapping ```` ```html ```` fence or chat text around the page is removed (notice `chat-text-removed`), an entity-escaped page is restored (notice `escaped-html-restored`). The new optional query parameter `verbatim=true` stores the content exactly as sent; `GET /api/html/{ns}/{id}/source` returns what was stored. 33 paths and 47 operations. No MCP release.

## Spec 1.134.0 — HTML files publish as pages

`POST /api/files` publishes a UTF-8 `.html`/`.htm` file sent to `public` without a password as an HTML page (same rules and limits as `POST /api/html`): `id`, `link` and `ownerLink` point to the page, notice `html-file-as-page`; `GET /api/files/{ns}/{id}` answers `308` to `/api/html/public/{id}` and `DELETE` removes the page. Other HTML files are stored and shown as source (notice `html-file-as-source`). If the same content is already published by someone else, that page is returned with notice `existing-page-not-owned` and the returned token cannot manage it. `POST /api/files`, `POST /api/html` and `POST /api/sites` document `403` "Upload refused"; the `PUT` 403 on HTML and sites reads "Missing or wrong owner token, or upload refused". Raw reads of `xml` pages answer `text/plain` (downloads keep `text/xml`); a site `entry` must be an HTML path, else the default entry is used and reported in notices. 33 paths and 47 operations. No MCP release.

## Spec 1.133.0 — Accurate gallery descriptions

`GET /api/gallery` descriptions now match behavior: public results cover live pages, files and sites; `q` searches titles (filename for files, id when untitled), not tags; `mine=true` with `X-Owner-Token` lists all of the caller's own pages, files and sites in any namespace, including password-protected ones, each with its `namespace` and `visibility`. `GalleryItem.type` is a page's stored format, `file` or `site`; KV and JSON stores are never listed. Description-only: 33 paths and 47 operations. No MCP release.

## Spec 1.132.0 — Report rate limit

`POST /api/reports` now documents `429` with the standard `ErrorResponse` when an address sends too many reports in a day; the response carries `Retry-After`. No other contract change: 33 paths and 47 operations. No MCP release.

## Spec 1.130.0 / MCP 1.12.1 — Comparison hub link

The contract description now links [brewpage.app/compare](https://brewpage.app/compare), which compares BrewPage with GitHub Pages, GitHub Gist, Netlify Drop, Cloudflare Drop, Tiiny Host and Static.app. Paths, operations and schemas are unchanged: 33 paths and 47 operations. MCP 1.12.1 links the comparison page from its README; same seventeen tools and behavior.

## Spec 1.125.1 — Format in the HTML create body

`HtmlUploadRequest` gains an optional `format` (same values as `?format=`); when both are sent, the body value wins. `PUT /api/html/{ns}/{id}` ignores a blank body `format`. A JSON object body without `content` is now published as the content itself with a `body-as-content` notice instead of `400`. No other contract change since 1.123.0: 33 paths and 47 operations. No MCP release; the server stays at 1.12.0 with the same seventeen tools.

## Spec 1.123.0 / MCP 1.12.0 — Upload limits endpoint and clearer site errors

New `GET /api/limits` (`getLimits`, tag `Limits`) returns the user-facing upload limits in bytes: `requestMaxBytes` and `sites` (`maxFiles`, `maxFileBytes`, `maxTotalBytes`, `maxArchiveExpansionBytes`, `maxPathChars`, `maxPathBytes`, `maxNameBytes`, `defaultTtlDays`, `maxTtlDays`, `allowedExtensions`, `skippedFileNames`, `skippedRootFolders`). A site now holds up to 200 files (was 100), 5 MB per file and 20 MB in total. Site uploads declare `413` (request over 25 MB, too many multipart parts or an overlong file name/path) and `422` when no servable file is left, which replaces `415`; a site limit hit answers `400` with a message naming the limit, as do a damaged, non-UTF-8 or password-protected ZIP and a `..` path. Unstorable metadata (control characters, over-long tags, NUL in content) is stored as the closest valid value with notices; data that still cannot be stored answers `400` instead of `409`. An upload the client aborts mid-body gets `408` with a JSON body from the edge instead of `503`. 33 paths and 47 operations. MCP 1.12.0 adds the `get_limits` tool and states the site limits and status codes in `publish_site` and `republish_site`; seventeen tools.

## Spec 1.121.0 — Paginated galleries index

The bot-friendly `GET /galleries` index is split into pages linked with `rel=prev/next`. The optional `page` query parameter is 1-based and defaults to the first page; an invalid number or a page past the last one answers `404`. Nothing else changes: 32 paths and 46 operations. No MCP release; the server stays at 1.11.0 with the same sixteen tools.

## Spec 1.119.0 / MCP 1.11.0 — Fixable inputs accepted with notices

Publish endpoints accept recoverable input mistakes and report each adjustment in an advisory `notices` array of `{code, message}` (`PublishNotice`) on successful create and update responses, omitted when empty. TTL accepts units and fractions (`2w`, `36h`) and is clamped to the allowed range; format aliases are mapped and unknown formats detected from content; site bundles skip unsupported members (422 only without an HTML entry); file types are sniffed with an inert `text/plain` fallback; namespaces are normalised; an empty `X-Password` means no password and a blank `X-Owner-Token` mints a new token. 32 paths and 46 operations. MCP 1.11.0 prints the notices, accepts string TTLs and free-form `format`; same sixteen tools.

## Spec 1.118.0 / MCP 1.10.0 — Mismatches reported, not rejected

Publishing and hosting requests no longer fail on delivery-mode or hosting-version bookkeeping. An explicit `path` where Dedicated subdomain is required publishes on the subdomain; a content update that turns a non-public `path` page into format `html` moves it to its subdomain and the old path redirects; `X-Delivery-Mode` on a content update is ignored; the hosting `PATCH` applies a stale `expectedVersion` (now optional) and answers locked modes and OLD links with `200` unchanged. Each such response carries `deliveryModeMatched: false`, `deliveryModeReason` (`policy:<code>`) and a human-readable `deliveryNotice`, now also on the hosting projection. The `PATCH` route also accepts sites and no longer declares `409`. `POST /api/files` no longer requires the multipart part to be named `file`; any single file part is accepted. 32 paths and 46 operations. MCP 1.10.0 `update_hosting` takes an optional `expectedVersion` and prints the notice; same sixteen tools.

## Spec 1.117.0 / MCP 1.9.5 — Delivery rules and safe Markdown

NEW sites and non-public HTML pages of format `html` require Dedicated subdomain; explicit `path` there answers `400 DELIVERY_MODE_REQUIRED`. Everything else in any namespace (Markdown, code/text, files, JSON, KV) now defaults to Promotion (`path`) and may choose `subdomain`; existing publications keep their mode. Markdown raw HTML is rendered through an allowlist: scripts, styles, event handlers, forms, frames/embeds and `meta`/`base`/`link` are removed, while media, `details`/`summary` and links (`http`, `https`, `mailto`, `tel`, relative) stay. Only `X-Delivery-Mode` descriptions and the hosting `PATCH` summary change in the spec: 32 paths and 46 operations. MCP 1.9.5 rewords its tool text accordingly; same sixteen tools and behavior.

## Spec 1.113.0 / MCP 1.9.4 — Publication outcome schema

The `result` object on HTML and site responses is described by a schema named `PublicationResult`. Its fields and values are unchanged, so responses are identical; code generated from the spec gets a new type name. Action `merged` means an existing publication was returned instead of a new one. File uploads that return an existing upload send `X-Existing-Resource: 1`, like HTML and sites. MCP 1.9.4 rewords its tool text accordingly; same sixteen tools and behavior. The contract still has 32 paths and 46 operations.

## Spec 1.108.0 — JPEG social preview images

Social preview images have a canonical URL: `GET /preview/{ns}/{id}.jpg` returns a 1200×630 JPEG card. The earlier `.png` URL keeps working for links already shared and serves the same JPEG bytes. Images of non-public or protected publications are marked `noindex`; if a card cannot be produced, the request redirects to the generic `/og-image.png?v=3`. The preview routes share one `preview` tag. The contract now has 32 paths and 46 operations. No MCP release; the server stays at 1.9.3 with the same sixteen tools.

## Spec 1.107.6 — Contract licence

The published contract states its licence again: `info.license` is `Apache-2.0`, the licence of this repository's contract and docs. The MCP server package stays MIT. Paths, operations and schemas are unchanged: 31 paths and 45 operations. No MCP release; the server stays at 1.9.3 with the same sixteen tools.

## Spec 1.107.4 — Contract metadata links

The published contract carries `info.termsOfService`, `info.contact` and a top-level `externalDocs` link to this site again. Paths, operations and schemas are unchanged: 31 paths and 45 operations. No MCP release; the server stays at 1.9.3 with the same sixteen tools.

## Spec 1.107.2 / MCP 1.9.3 — Backend-generated contract

The public contract is now generated by the BrewPage backend; the YAML file and the JSON copy this site renders are derived from that export, and its provenance is committed with it. Administrative routes are not part of the public artifacts. The sync corrects schema, access and serialization details and adds no endpoint.

MCP 1.9.3 is a metadata patch: tool descriptions are clearer about unlisted link access, returned links, limits and expiry. Same sixteen tools, input defaults and HTTP behavior.

## MCP 1.9.2 — Exact dependency versions

The MCP server and the docs site now declare exact dependency versions, so an installed server uses the same SDK and `zod` versions it is built and tested with. No functional change; the spec stays at 1.104.0 and the same sixteen tools are available.

## MCP 1.9.1 — Dependency maintenance

Refreshed the locked dependency versions used to build and test the server and the docs site. No functional change; the spec stays at 1.104.0 and the same sixteen tools are available.

## Spec 1.104.0 / MCP 1.9.0 — Delivery reason on HTML responses

`POST /api/html` and `PUT /api/html/{ns}/{id}` responses may now carry two optional strings, `deliveryModeReason` and `deliveryNotice`. A public HTML or Markdown page created without `X-Delivery-Mode` may be published on its own subdomain when it needs browser features a BrewPage link does not provide; the response then says `auto:<codes>`. `advisory:<codes>` means the address was not changed. Send `X-Delivery-Mode: path` to keep a BrewPage link, and always use the returned `link`. Existing clients see no difference when the fields are absent.

The spec also documents `visibilityNotice` on HTML responses, `result` on the update response, the optional `format` on `PUT /api/html/{ns}/{id}`, and the `200` response with `X-Existing-Resource: 1` returned when a repost matches a page that is already published.

MCP 1.9.0: `publish_html` and `update_html` print `deliveryModeReason` and a `Delivery notice:` line when the server returns them. Same sixteen tools, no input changes.

## Spec 1.31.0 / MCP 1.4.0 — Content-Type fallback on `POST /api/html`

`POST /api/html` and `PUT /api/html/{ns}/{id}` now accept raw `text/*` bodies and (POST only) `application/octet-stream`. Binary payloads sniffed as PNG, JPEG, GIF, WEBP, MP4, PDF or ZIP auto-route to `/api/files` and return a 201 with the file resource location. The existing `application/json` contract is unchanged — JSON clients see no difference.

`UnsupportedFileTypeException` now responds with **422 Unprocessable Entity** (was 415). Both 415 and 422 error bodies expose a `supportedTypes` array on `ErrorResponse` listing the MIME types the endpoint accepts, so clients can surface actionable guidance.

For the full MIME → format dispatch table and ready-to-paste `curl` examples, see the live BrewPage [`/llms-full.txt`](https://brewpage.app/llms-full.txt). The interactive OpenAPI explorer is published at [kochetkov-ma.github.io/brewpage-openapi](https://kochetkov-ma.github.io/brewpage-openapi/).
